jooling gives hourly workplaces one dependable source of truth for scheduled work. Managers plan and publish from the web application. Workers use mobile—or the worker web experience—to see work, respond to changes, manage availability, and track time.

![The manager Overview with the week's staffing picture](/screenshots/overview.png)

<Callout type="info" title="The core promise">
A published schedule is an immutable operational record. Later changes are prepared privately and published as a new version; history is never silently rewritten.
</Callout>

## End-to-end lifecycle

1. A Manager creates a Workplace, adds Locations and Positions, and invites Workers.
2. Workers record Unavailability, Work Preferences, and Time-off Requests.
3. A Manager prepares a Location-specific weekly Schedule and resolves conflicts.
4. Publishing creates an immutable Schedule Version and notifies affected Workers.
5. Workers acknowledge that they saw it. Late material changes may separately require Shift Acceptance.
6. Coverage, time clock, timesheets, announcements, messages, and reports support daily operations.

## Product boundaries

jooling includes scheduling, publication, leave, coverage, time tracking, labor visibility, communications, and subscriptions. Your Workplace decides which features and policies are enabled for your team.
